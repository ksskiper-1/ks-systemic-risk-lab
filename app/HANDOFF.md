## 2.2. Соглашения и ловушки

- **Направление E.** `E[i, j]` — требование i к j. Потери кредитора i при падении j: `(1−R)·E[i,j]`. В коде: `L = L0 + (1−R)·(E @ D)`; в пакетном виде `D @ E.T`. Ошибка ориентации меняет результаты полностью.
- **Очередь спасения** `order_by_liab(E)`: сортировка по `E.sum(0)` (сумма по столбцу, то есть сколько в банк j вложили остальные), по убыванию, ничьи по меньшему номеру.
- **Порог дефолта:** `L >= K − EPS`, EPS = 1e-12, включительно. Банки, упавшие от шока (`L0 >= K − EPS`), не спасаются.
- **Спасение:** вливание `L − K + 1e-9`, если не больше остатка бюджета; неподъёмные пропускаются; спасённый банк может упасть снова.
- **Механизм `res`:** `K = Kb + 0,02·A`. Механизм `sup`: бюджет `0,03·ΣKb` (около 5,3), в `precompute` бюджет можно задать вручную (`Gabs`).
- **Нормировка размера каскада:** на N (не N−1). В концепции встречается N−1: нужна одна версия.
- **Случайные числа:** `SeedSequence([base, topo, rep, stream])`; капитал берётся из потока `(base, 9, rep, 2)` и поэтому одинаков в обеих топологиях. Основная серия base = 2026, пилот для δ base = 7777. Нарушение порядка вызовов случайных чисел меняет результаты (особенно в bootstrap: `hypothesis.boot` и `precompute.boot_ci` должны давать один поток индексов).
- **Одиночный шок в движке:** шаг-функция (результат не зависит от s при s ≥ k_i); в `contagion.single_curves` то же свойство используется для ускорения, считается только участок s < k_i.
- **Метрика S:** `S_ind = Σ[min(L,K) − min(L0,K)]/ΣA`. `K` — тот, что передан в функцию (для `res` это капитал с резервами; см. открытый вопрос 1). Вливания поддержки в K метрики не входят, стоимость возвращается отдельно (`spent`).
- **S_ind немонотонна по s** (банк, потерявший капитал напрямую, выпадает из «вызванных»); S_total монотонна. Это ожидаемо и не ошибка.
- **Интерфейс:** клик по банку работает через 25 скрытых кнопок `pick_<i>` в контейнере `pickers`; JS во фрейме нажимает `parent.document.querySelector(".st-key-pick_<i> button")`.
