## 3. Модель

### 3.1. Сеть (`engine.gen_net`)

- 25 банков, суммарные активы 2500 (по 100 у каждого), капитал банка κ·A, где κ ~ U(0,04; 0,10). Капитал одинаков в обеих топологиях (отдельный поток случайных чисел).
- `E[i, j]` — требование банка i к банку j. Если j падает, теряет кредитор i. Размер связи: α·A_i·w, где w берётся из распределения Дирихле, α по умолчанию 0,5.
- **Распределённая:** каждый банк кредитует случайные max(1, Poisson(3)) других.
- **Концентрированная:** 5 центральных банков (0–4) связаны между собой и ещё с тремя периферийными каждый; 20 периферийных кредитуют по 2 из 5 центральных.
- Воспроизводимость: `SeedSequence([base, topo, rep, stream])`. Основная серия base = 2026, пилот для порога δ base = 7777.

### 3.2. Каскад дефолтов (пороговая модель)

- Шок: L0_i = s·A_i. Банк падает от шока, если L0 ≥ K (допуск EPS = 1e-12).
- Передача: L = L0 + (1−R)·E·D, где D — множество упавших банков, R = 0,4 по умолчанию. Новые падения, пока они возникают.
- Механизмы (`mech_setup`):
  - **none:** без помощи;
  - **res:** резервы, K + 0,02·A (RHO = 0,02);
  - **sup:** государственная поддержка, бюджет G = 3% суммарного базового капитала (≈ 5,3). Спасение = вливание дефицита L−K, очередь по убыванию входящих обязательств (ничьи по меньшему номеру), банки, упавшие от шока напрямую, не спасаются, неподъёмные пропускаются, спасённый банк может упасть снова.

### 3.3. Метрики (`engine.metrics`)

Шкала шока: сетка s от 0 до 0,15 с шагом 0,0005 (301 точка).

| Метрика | Смысл |
|---|---|
| A1 | интеграл масштаба каскада при шоке одного банка (ступенька: результат не зависит от s при s ≥ k_i) |
| A2 | интеграл доли вторичных дефолтов по s при общем шоке (трапеции) |
| C06, C08, C10 | доля вторичных дефолтов при общем шоке 6, 8, 10% |
| FS | доля активов, взвешенная по банкам, которые могут запустить каскад размером выше θ = 10% |
| KSTI | взвешенная по активам сумма критических порогов банков |
| c1 | размер каскада от шока на один банк (вектор по банкам) |

Замечание: размер каскада нормируется на N, а не на N−1 (в концепции и в коде это приходится держать согласованным).

## 4. Гипотеза и результат протокола

**H:** эффект государственной поддержки на каскады зависит от структуры сети и различается при шоке одного банка и при общем шоке.

Статистика: T = Δ(один банк) − Δ(общий шок), где Δ = (A конц., поддержка − A конц., без помощи) − (A распр., поддержка − A распр., без помощи). Доверительный интервал: bootstrap, 10 000 повторов, сети пересэмплируются независимо по топологии.

Правило исхода (`hypothesis.verdict`): «поддержана», если ДИ не содержит 0, |T| ≥ δ и знак T сохраняется не менее чем в 90% ячеек сетки чувствительности; «не поддержана», если ДИ целиком внутри ±δ; иначе «неустойчиво». Выборка в режиме протокола растёт 100 → 300 → 1000, пока ширина ДИ не станет меньше δ.

**Воспроизведено (`check_protocol.py`, 100 сетей, seed 2026):**

- T = +0,0107, 95% ДИ [0,0085; 0,0129], порог δ = 0,0051.
- Δ(один банк) = +0,0101, Δ(общий шок) = −0,0006.
- Знак T сохраняется в 27 из 27 ячеек сетки R × α × G. Исход: «гипотеза поддержана».

Дополнение вне протокола (α = 0,1 и 0,2, 300 сетей): T = +0,0007 [0,0001; 0,0012] и T = +0,0042 [0,0033; 0,0050]. Эффект исчезает в сильно разрежённых сетях.

## 6. Ядро заражения `contagion.py`

Назначение: показывать системный риск как непрерывную потерю, а не только число упавших банков. Движок не изменён.

**Динамика.** h_i = min(1, L_i/K_i) — доля потерянного капитала. Потери пересчитываются с нуля на каждом шаге (повторного учёта нет):

L = L0 + (1−R)·E·h,  h = min(1, L/K).

Если заменить h на индикатор дефолта, получается пороговая модель из `engine.py`.

**Метрика S** (абсолютная потеря в единицах активов, нормировка на суммарные активы):

- S_total = Σ min(L_i, K_i) / ΣA;
- S_ind = Σ [min(L_i, K_i) − min(L0_i, K_i)] / ΣA — потери, вызванные заражением (аналог вторичных дефолтов).

S_ind может убывать по s (банк, потерявший капитал напрямую, выпадает из «вызванных»), как и число вторичных дефолтов; S_total растёт монотонно.

**Функции:**

- `propagate_batch` — распространение без поддержки, пачкой строк;
- `propagate_one` — одна строка, с поддержкой (правила как в движке, параметр `target` задаёт долю потери капитала после спасения);
- `induced_S` — S_ind или S_total;
- `single_curves` — кривые S при шоке одного банка (считается только участок s < k_i, дальше результат постоянен);
- `metrics_S` — аналог `engine.metrics`: A1S, A2S, A2St, S06/S08/S10, вектор S1 по банкам, затраты на поддержку, `rho` и `sat_share` (раздел 16);
- `M_matrix`, `spectral_radius`, `saturated_share` — диагностика режима (раздел 16).

**Неподключено:** ядро не вызывается из `app.py`, `hypothesis.py` и `hyp_view.py`; T по метрике S не считался.

### Нерешённые вопросы по модели

1. **Резервы.** Если измерять потери до капитала с резервами, S растёт (демонстрационная сеть: A2S 0,00401 против 0,00245 без резервов), потому что резервы поглощают больше капитала. Если измерять до базового капитала Kb, значение совпадает с «без резервов». Предложение: измерять до Kb, резервы учитывать только в динамике.
2. **Поддержка.** Вливание только дефицита в непрерывной модели не гасит передачу стресса: банк с полностью потерянным капиталом остаётся в стрессе (h ≈ 1). На демонстрационной сети A1S и A2S для `sup` совпали с «без поддержки» до 5-го знака, а вливание до target = 0,5 при бюджете ≈ 5,3 недоступно. Проверено на одной сети, на серии не проверялось. Варианты: оставить как результат («вливание дефицита не гасит заражение»), задать другое правило спасения, проверить бюджеты G = 25 и 50.

Приложение запускается командой `streamlit run app.py` и состоит из двух разделов.

**«Сеть и каскад»:**

- граф: кольцо вокруг банка показывает долю потерянного капитала, полное мигающее кольцо означает, что банк упадёт на следующей волне; кнопка паузы / продолжения / показа сначала, точки шагов;

## 9. Тест KSTI

Данные: 300 сетей на страту, обе топологии, три механизма, θ = 5, 10, 20%. Сравнивается качество предсказания размера каскада вне выборки (кросс-валидация 5 × 10), добавочный эффект KSTI с доверительными интервалами.

- R² регрессии KSTI на FS равен 0,998–0,999 во всех шести стратах: KSTI почти линейная функция FS. Математически KSTI = (1 − FS) + Σ w·v·k, то есть FS плюс капитал банков-триггеров.
- Для исходов A2 и A2S, не зависящих от вектора c1: при базе «FS + средний k» медиана добавки KSTI равна −0,0001, практически значимое улучшение (Δ ≥ 0,01) есть в 3 из 24 сравнений. При базе «только FS» KSTI выглядит сильно полезным (медиана +0,19), но это подмена среднего капитала.
- Для A1 и A1S (строятся из того же c1) KSTI добавляет заметно (в 18 из 24 сравнений), но связь частично механическая, вывод слабый.
- FS плохо объясняет исходы при общем шоке (R² не выше 0,05).

**Вывод:** KSTI корректно называть производной метрикой (FS с поправкой на капитал); независимой информации сверх FS и среднего капитала он не даёт. Основной вывод проекта строится на метрике A.

Оговорки: тест вне заранее заданного протокола, используются те же сети seed 2026, что и в основной серии; множественные сравнения; при очень малых эффектах статистическая значимость есть, а практической нет.

**Подтверждено и важно:**

1. **Насыщение метрики S (существенное ограничение расширения).** При α = 0,5 спектральный радиус матрицы (1−R)·E/K в среднем 4,58 (>1), поэтому любой положительный общий шок усиливается до полного стресса: S_total достигает ΣK/ΣA уже при шоке 1%. Из-за этого A2S одинаков в обеих топологиях (парная разность 0, 100 сетей). ## 16. T1: диагностика режима в `contagion.py` (25 октября)

Статус: исследовательское дополнение, вердикт v1.3 не меняет. `engine.py` и файлы `results/` не изменены.

**Определения (код в `contagion.py`):**

- `M_matrix(E, K, R)` = diag(1/K)·(1−R)·E, то есть M[i, j] = (1−R)·E[i, j]/K_i (строка делится на капитал кредитора i). При h < 1 динамика линейна: L = L0 + K·(M h).
- `spectral_radius(E, K, R)` = max |λ(M)|. Спектр не зависит от ориентации E (diag(1/K)E, E·diag(1/K) и транспонированная матрица подобны), поэтому ориентацию проверяет связь M с динамикой, а не ρ.
- `saturated_share(E, A, K, R, s_ref=0.01)` = доля банков с h_i ≥ 1 − 1e-9 (константа `SAT_TOL`) после распространения при общем шоке L0 = s_ref·A, непрерывная модель без помощи. A нужен для формирования шока. Считаются все банки, в том числе насыщенные самим шоком; при s_ref = 0,01 и k_i ≥ 0,04 таких нет.
- `metrics_S` возвращает два новых ключа: `rho` (по капиталу механизма, для `res` с резервами) и `sat_share` (всегда без помощи, при `s_ref` = 0,01 по умолчанию). Аргумент `rho` у `metrics_S` по-прежнему означает ставку резервов; совпадение имён оставлено, чтобы не менять сигнатуру.

**Тесты** (`check_contagion.py`, блоки 8–9, ненулевой код выхода при нарушении):

- E = [[0,50],[50,0]], K = 10, R = 0,4: ρ = 3, sat_share = 1;
- нулевая E при K = 10 и A = 100 (прямой шок 1 не исчерпывает капитал): ρ = 0, sat_share = 0; контроль: при K = 0,5 банки насыщены самим шоком, sat_share = 1;
- ручной пример E[0,1] = 30, K = 10, A = 100: при шоке 5% sat_share = 1/3, при 1% sat_share = 0;
- ориентация M и тождество L = L0 + K·(M h) на сети seed 2026; sat_share в [0, 1] и кратна 1/N; ρ линеен по α; sat_share = 1 тогда и только тогда, когда S_total(1%) на потолке ΣK/ΣA; ключи `metrics_S` совпадают с отдельными функциями;
