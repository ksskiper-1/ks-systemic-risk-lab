## 1. Назначение и границы

Цель: описать, как мера заражения типа DebtRank на основе потери капитала (S) различает две топологии сети в зависимости от доли межбанковских требований α, и сопоставить это различие с режимом передачи (ρ, sat_share).

Ожидаемого результата нет. Документ не назначает интерпретацию заранее и не предполагает, что S окажется информативной или неинформативной.

**Не входит в дополнение:**

- T по метрике S и механизмы «резервы» и «поддержка» в S (решение автора по рабочему заданию от 25.10.2026; основание: `results/exploration_support_S.txt`);
- новая версия DebtRank (основание: `results/exploration_once_debtrank.txt`);
- изменение N (N = 25), R, протокола v1.3 и `engine.py`.

Открытые развилки, перенесённые из `PROJECT_STATUS.md`, решены одной строкой: **в v1.4-ext S считается только без помощи; вопросы резервов (Kb или Kb + резервы) и правила поддержки для S не рассматриваются.**

## 2. Модель и определения

Код: `contagion.py` (md5 f9205f3423, состояние после T1) и `engine.py` (md5 66b1fbd2b9, не изменялся). В T3 md5 обоих файлов записываются в JSON. Если на момент запуска md5 другой, расчёт останавливается.

| Обозначение | Определение | Функция |
|---|---|---|
| Сеть | `gen_net(topo, rep, N=25, alpha=α, base=2027)`; topo 0 — распределённая, 1 — концентрированная; ΣA = 2500, A_i = 100, K_i = Kb_i = κ_i·A_i, κ ~ U(0,04; 0,10) | `engine.gen_net` |
| Режим | механизм `none` (без помощи), K = Kb; R = 0,4 | `engine.mech_setup('none', …)` |
| E | E[i, j] — требование банка i к банку j; при стрессе j теряет кредитор i | — |
| Динамика | L = L0 + (1−R)·E·h, h = min(1, L/K), потери пересчитываются от L0 на каждом шаге до неподвижной точки | `contagion.propagate_batch` |
| M | M = diag(1/K)·(1−R)·E, M[i, j] = (1−R)·E[i, j]/K_i | `contagion.M_matrix` |
| ρ | max \|λ(M)\| | `contagion.spectral_radius` |
| S_total(L0) | Σ_i min(L_i, K_i) / ΣA | `contagion.induced_S(…, total=True)` |
| S_ind(L0) | Σ_i [min(L_i, K_i) − min(L0_i, K_i)] / ΣA | `contagion.induced_S` |
| A2S | ∫ S_ind(s) ds при общем шоке L0 = s·A по сетке s = 0; 0,0005; …; 0,15 (301 точка), метод трапеций | `metrics_S(...)['A2S']` |
| A1S | Σ_i w_i ∫ S_ind,i(s) ds при шоке s·A_i на одном банке i, w_i = A_i/ΣA, та же сетка | `metrics_S(...)['A1S']` |
| sat_share | доля банков с h_i ≥ 1 − SAT_TOL после распространения при опорном общем шоке L0 = s_ref·A, без помощи; учитываются все банки, включая насыщенные самим шоком | `contagion.saturated_share` |

Пояснения:

- ρ при h < 1 описывает линеаризованную передачу: ρ < 1 — затухание, ρ > 1 — усиление. Режим насыщения определяется по sat_share, а не по одному ρ.
- α меняет только веса связей (E = α·A_i·w), структура и веса Дирихле от α не зависят. Поэтому для одного (topo, rep) сети при разных α отличаются только масштабом E, а ρ линеен по α (проверено в `check_contagion.py`, блок 8).
- Капитал берётся из потока `(base, 9, rep, 2)` и одинаков в обеих топологиях при одном rep. На этом основана парность.

## 4. Основной эффект и интервал

Для каждого α:

- d_rep(α) = A2S(topo 1, rep) − A2S(topo 0, rep) по всем парам, где оба расчёта сошлись (раздел 6);
- **D(α) = среднее d_rep(α)** по n_ok(α) таким парам;
- bootstrap: `idx = rng.integers(0, n_ok, (B, n_ok))`, D*_b = mean(d[idx_b]), 95% percentile-интервал [L, U] = percentile(D*, [2,5; 97,5]). Индекс пары пересэмплируется целиком, то есть обе топологии берутся вместе;
- ширина интервала w(α) = U − L.

**Вспомогательные показатели** (описательные, в критерии не входят):

- r(α) = D(α) / mean A2S(topo 0, α) по той же основной серии. Знаменатель указывается явно;
- среднее \|d_rep(α)\|. Это другая величина, чем D(α): средний модуль парной разности не равен модулю разности средних;
- по каждой топологии: среднее и медиана A1S, A2S, ρ, sat_share;
- для A1S: среднее парной разности и её 95% ДИ, без δ и без классификации.

## 5. Критерии интерпретации D(α) относительно δ_S(α)

Используется 95%-й percentile-bootstrap интервал [L, U] из раздела 4. Правила применяются отдельно к каждому α, в указанном порядке; ярлыки взаимоисключающие.

0. **«не интерпретируется: неполная сходимость»** — при любой несходимости для этого α (раздел 6).
1. **«порог вырожден: вердикт не выносится»** — если пилотная медиана A2S равна нулю, то есть δ_S(α) = 0. Запрещены оба вердикта: «практически эквивалентны» и «практически значимое различие». Показываются только описательные результаты: D(α) и 95%-й интервал [L, U]. Причина: при δ_S = 0 правило 3 (L > δ_S или U < −δ_S) превращается в обычную статистическую значимость, а не практическую.
2. **«практически эквивалентны»** — интервал строго внутри ±δ_S: −δ_S < L ≤ U < δ_S.
3. **«практически значимое различие»** — весь интервал за границей практической значимости: L > δ_S или U < −δ_S. Знак указывается: D > 0 означает, что потери от заражения выше в концентрированной сети.
4. **«неопределённо»** — все остальные случаи.

Правила 2 и 3 не могут выполниться одновременно. Если интервал не содержит 0, но ярлык «неопределённо» или «практически эквивалентны», это указывается пометкой «различие статистически обнаружимо», без смены ярлыка.

Правило эквивалентности по 95%-му интервалу строже стандартного TOST на уровне 5%, где обычно используют 90%-й интервал ([Lakens, Equivalence Testing and Interval Hypotheses](https://lakens.github.io/statistical_inferences/09-equivalencetest.html)). Это сознательно консервативный выбор, и стандартным TOST он не называется.

Порог δ_S = 10% пилотной медианы — рабочий критерий этого исследования, по аналогии с v1.3, а не общепринятая граница существенного эффекта.

**Известное ограничение.** Если δ_S(α) численно ничтожен, но не равен нулю, правило 3 по смыслу близко к статистической значимости, а ярлык может быть неустойчив к малым изменениям пилотной медианы. Отдельного правила для этого случая нет: ярлык присваивается по правилам 2–4, а значение δ_S(α) всегда публикуется рядом с ярлыком, чтобы читатель мог оценить этот риск.

**Обобщённого вердикта по сетке α нет.** Результат — таблица из восьми ярлыков с D, [L, U] и δ_S. Интервалы поточечные: каждый относится к своему α, совместного 95%-го покрытия для всех α они не дают. Поправка на множественные сравнения не применяется.

Выборка фиксирована (200 пар). Если w(α) ≥ 2·δ_S(α), ярлык 2 недостижим по построению. Это сообщается рядом с ярлыком и не является поводом увеличить выборку после расчёта.

ρ и sat_share в критерии не входят. Связь ярлыков с режимом (ρ, sat_share) описывается в тексте как наблюдение, без заранее назначенных порогов.

## 6. Несходимость

`propagate_batch` выбрасывает `RuntimeError`, если строка не сошлась за MAXIT итераций. Код ядра в T2 не меняется, поэтому правило задаётся для скрипта T3. Несходимость может зависеть от свойств сети и режима заражения, поэтому исключение несошедшихся пар способно сместить оцениваемую совокупность. Малая доля исключений этого риска не снимает, отсюда консервативное правило:

1. Каждый вызов (`metrics_S`, `spectral_radius`, `saturated_share`) для данного (α, topo, rep) выполняется в отдельном `try`. При `RuntimeError` в CSV пишется `status = nonconv` и указывается, какой расчёт не сошёлся. Числовые поля этой строки остаются пустыми (NaN). Сведения о сбое сохраняются полностью.
2. Сети не заменяются, TOL и MAXIT автоматически не меняются ни до, ни после запуска.
3. **При любой несходимости** в основной серии для данного α (в любом из расчётов A1S, A2S, sat_share) основной ярлык этого α — «не интерпретируется: неполная сходимость». D(α) и [L, U] по полным парам публикуются только описательно, с числом и номерами исключённых пар.
4. Пилот: δ_S(α) не вычисляется по молча сокращённой выборке. Если хотя бы одна пилотная сеть при этом α не сошлась по A2S, δ_S(α) не определён, ярлык — «не интерпретируется: неполная сходимость». Медиана по сошедшимся пилотным сетям может быть показана только описательно, с пометкой.
5. Несходимость ρ невозможна: собственные значения считаются напрямую.

Это правило не предполагает, что хотя бы одна реализация обязательно не сойдётся.
